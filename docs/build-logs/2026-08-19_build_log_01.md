| Time | Commit | Description |

## What was built

### 1 — Night-side objects stay visible

Two independent sun effects stacked to make the night half of every globe page
unreadable, which is the half an operator most needs:

| Layer | What it did | Change |
|---|---|---|
| `SatEngine._refreshOcclusion` | multiplied each dot's alpha by `eclipseShadowFactor` at cinematics `'high'` | eclipse pass removed; only the camera-based `farSideFade` remains |
| Cesium globe lighting (3 pages) | `enableLighting` + `dynamicAtmosphereLighting*` painted the night side near-black, so even a full-alpha dot had no contrast | all three set explicitly `false`; `nightFade{In,Out}Distance` dropped |

The distinction that drove the fix: **a sun cue is a lighting cue, not a
tracking cue.** Camera occlusion stays, because a dot genuinely behind the
Earth *from this viewpoint* is a depth cue about the current view.
`eclipseShadowFactor` itself stays in `astro.js` and stays tested — a future
"sunlit / eclipsed" badge is exactly what it is for; it just must not touch
opacity again. `cinematics` now gates only bloom + the star skyBox.

### 2 — Constellation fly-in altitude is derived, not hardcoded

The fly-in was a fixed 22,000 km, which frames LEO. GPS (~20,200 km) and
Galileo (~23,200 km) are MEO — their shells sit at or beyond that camera, so
only ~9 of 32 sats landed on canvas, in the corners behind the HUD. Plane
rings still drew, sweeping off-screen, which made it read as "the tab renders
nothing" rather than "the camera is inside the shell."

`flyInAltitude(data)` derives distance from the shell radius as geometry, not a
tuned constant: the plane *ring* extends a full shell radius in every direction
from Earth's centre, so `d = r / tan(halfAngle)`. Two traps worth recording:

- A **tuned multiplier under-frames.** A first pass at 1.9 still ran the rings
  off every edge, because a ratio picked against the sats' scatter ignores that
  the ring is a full diameter wide.
- **Cesium applies `fov` to the *wider* screen axis.** Framing off the vertical
  fov alone fit only 19 of 32 GPS sats at 390px while desktop looked fine — the
  maths was right for the axis it measured and blind to the one that clipped.
  `frameHalfAngle()` takes the min of both axes.

`FRAME_MARGIN` (0.75) shrinks the half-angle rather than padding the distance,
which doubles as the HUD correction — the stats/planes/density panels overlay
the corners, so a ring that mathematically just fits still lands underneath
them. Floor is the old LEO framing; cap is `tuneCameraLimits`'
`maximumZoomDistance`, so the fly-to can never request a camera the controller
would refuse.

Also fixed on the same path: `introFlyIn()` now takes `currentData`, not the
local `data` — on the load-failure path there is none, and `flyInAltitude`
falls back to the LEO framing rather than throwing.

## Bugs found & fixed

| # | Bug | Root cause | Fix |
|---|---|---|---|
| 1 | `/constellations/` HOME link rendered as a default blue underlined anchor, unlike every other page, and **could not be clicked** | `.spacetrack-nav` sets `pointer-events: none` so the bar does not block the globe; each child re-enables it with `pointer-events: auto`. The brand's rule body — including that re-enable — lived only in `orbit.css` and `spacetrack.css`, duplicated between them. `/constellations/` links `tokens.css` + `chrome.css` + `constellations.css` and **neither** of those two, so it got UA anchor styling *and* inherited `pointer-events: none` | Moved the shared brand body into `css/chrome.css`, which every app page links. Deleted `spacetrack.css`'s now-redundant copy; trimmed `orbit.css`'s to just its three logo-layout properties |

The class was already uniform in the markup — all three pages ship
`<a href="/" class="spacetrack-nav__brand">◂ HOME</a>`. This was purely a
question of which stylesheet owned the rule, which is why it survived a visual
pass on the two pages that did link it.

## Known state (not a regression, deliberately not changed)

`/spacetrack/` computes `display: flex` for the brand because it links
`../orbit/orbit.css`. That was already true before this change — `orbit.css`'s
full body applied there — so `spacetrack.css`'s old comment claiming "this
page's brand is text-only" was describing a rule production was not using.
Left as-is rather than altering that page's layout as a side effect of a
one-line fix.
