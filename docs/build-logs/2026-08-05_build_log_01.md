## Plan 34 Phase 3.2 — constellation / orbital-plane view (spec #7)

The full batch (C1–C3) landed in this session's commits; C2 was the bulk.

### C1 — `public/constellations/compute.js` + tests

- Pure plane arithmetic, no Cesium/DOM/satellite.js: `smaKmFromMeanMotion` (Kepler,
  n rad/min→rad/s), `altKmFromSma`, `planeElements({raanRad, inclRad, noRadPerMin})` →
  `{raanDeg, inclDeg, smaKm, altKm, shell}`, `circularMeanDeg` (wrap-aware, normalised
  to [0,360) with a 1e-6° wrap-residue collapse), `groupIntoPlanes` (gap-clustering on
  circular RAAN anchored at the largest gap so planes straddling 0°/360° stay whole),
  `planeRingDeg` (great-circle ring as {lat,lon}° directions; radius applied caller-side).
- 15 checks wired into the orbit-ingest `npm test` chain (after catalog-compute).

### C2 — the `/constellations/` page

- **Data**: Celestrak group TLEs via the existing `/api/tle` proxy (groups `starlink`,
  `oneweb`, `gps-ops`, `galileo`, `iridium-NEXT` — all in `ALLOWED_GROUPS`); starlink
  via `parseTLEChunked` (~8000 TLEs), others `parseTLE`. Every constellation loads fully
  at boot (density slider max = total from the start — **no fetch-all button**). Cache
  keyed per constellation; switching never refetches.
- **Grouping**: the plan's "RAAN+incl+SMA" is realised as `groupConstellation`:
  inclination-band gap-split (`inclTolDeg: 1.0`) first, then `groupIntoPlanes` (RAAN
  gap-split, 5°) per band — see issues log; live Starlink needs the two levels.
- **Render**: per-plane two-ring glow (width 1.2 glow 0.15 alpha 0.25 + width 0.6 glow
  0.08 alpha 0.12, `arcType: ArcType.NONE`, 180 segments) via `engine.addManagedEntity`;
  sats via `engine.addSatellite(satrec, shellColor, 3, false, meta)` with `show`
  toggling for the density cap, progressive fill plane-major (planes by RAAN, then
  members). Rings are Earth-fixed schematics like the GEO belt (RAAN is inertial).
- **UI**: 5-button selector bar (STARLINK/ONEWEB/GPS/GALILEO/IRIDIUM, primary control,
  fixed under the topbar), stats HUD (LOADED/RENDERED/PLANES/AVG ALT/AVG PERIOD + LIVE),
  planes HUD (rows `P01 · RAAN 44° · 155 · LEO`, click → fly-to that plane's ring via
  `BoundingSphere.fromPoints(ringPositions)` + `flyToBoundingSphere`), density HUD
  (slider min 40 step 10 + revs-toggle), sat-bar, time-warp 0/1/10/100/1000 + recenter +
  cam-alt, inspector (GROUP/PLANE/NORAD/LAT/LON/ALT/VEL/PERIOD/REGIME), footer citation +
  mission clock. `?c=` preset param, default `starlink`; `window.__constellations`
  debug handle; `beforeunload → engine.destroy()`.
- **Layout decisions** (deviations from the C2 prep notes): mobile breakpoint **768px**
  (was 600px); the hamburger reveal lives in constellations.css (orbit variant) — it
  grows the nav 34→64px, which invalidates every prep-note offset; HUD tops desktop
  96px / mobile 136px; mobile top HUDs **stack** (stats 136, planes 208) because the
  side-by-side toggles (~200px each) overlap at 390px; inspector desktop bottom-LEFT
  (density owns bottom-right); landscape-short keeps the 136/208 stack (clears both nav
  shapes).
