## What was built

### 1 — `loadSourceIndex()` fetches and parses GCAT

The object-profiles pipeline (Tasks 1–10) was deployed but the fact source was a
stub: `loadSourceIndex()` returned `new Map()`, so `runFacts` wrote nothing and
`orbit-profiles` D1 was empty.

New `workers/orbit-profiles/src/gcat.js` — pure, fixture-testable:

| Function | Does |
|---|---|
| `parseTsv(text)` | GCAT's `#`-header TSV. Skips the `# Updated <date>` comment line below the header, trims space-padded fixed-width cells, tolerates short rows. |
| `parseOrgs(text)` | `orgs.tsv` → `Map<code, {name, ename, shortEName, stateCode}>`. |
| `mapStatusCode(raw)` | GCAT phase code → `in orbit` / `decayed` / `landed` / `deep space` / null. Exact match, not prefix. |
| `buildGcatIndex(satcat, orgs)` | `Map<canonical COSPAR, {byField, spine}>` — the shape `resolveConflicts` + `writeFacts` already take. |

`loadSourceIndex(env)` in `index.js` is now the thin fetch shim (URLs
overridable via `env` for pinning). GCAT supplies `official_name`,
`operator_name`, `owner_country`, `bus`, `manufacturer`, `launch_mass_kg`,
`status`. `mission_summary` / `mission_type` / `power_w` / `design_life_years`
stay null — those are NSSDCA's, and NSSDCA has no bulk dump (a later task). The
merge point is written out at the seam in `loadSourceIndex`.

### 2 — `seedSources` runs as a pipeline step

`seedSources()` (Task 2) was tested but never called. `facts.js` enforces the
allowlist against the `SOURCES` *constant*, so writes did not fail — but the
`sources` table stayed empty and the UI renders attribution from that table.

`runProfiles` now runs it as a reported `seed-sources` step before any stage,
unconditionally (4 idempotent upserts), injectable for tests.

### 3 — English names, complete Status map (the two bugs the first run surfaced)

Verified against the live API after the first full `facts` run:

- **`owner_country` was the transliterated native name** ("Zhonghua Renmin
  Gongheguo"). `parseOrgs` read GCAT's `Name`; `ShortEName` is the usable label.
  Now: a country (`State` column) resolves as `ShortEName || EName || Name`; an
  organisation (`Owner`/`Manufacturer`) as `EName || Name` (EName is `-` for
  many orgs). Live facet went to USA / China / Russia / USSR / UK / France / …

- **`status` was null for docked/grappled objects** — the whole ISS complex.
  `mapStatus` handled O/OX/R/D/L by prefix, so `GRP`/`DK`/`AO` fell through and
  `E` (exploded) wrongly matched `EO` (escape). Replaced with an exact-match
  table over GCAT's full phase vocabulary. Docked/grappled/berthed → "in orbit";
  all reentry codes → "decayed".

Both fixes needed a full `facts` re-run. `writeFacts`' `ON CONFLICT DO UPDATE`
only touches spine columns, so `prose`/`prose_tier` survived — `prose` did not
need re-running. Reset the checkpoint, re-dispatched, verified 0 rows left with
the old country string.

## Open follow-up — batch the stage loops

Each stage took ~2.7 h (`prose` 5.8 h — hit `timeout-minutes: 350` at 82%,
auto-resumed). Cause: `runMatch`/`runFacts`/`runProse` do 1–2 D1 round trips
**per object** over the HTTP API from a GitHub runner. `writeFacts` uses
`db.batch()` but the loop calls it once per row. Batching the loops (~25–50
objects per `batch()`) cuts round trips ~25× → each stage in minutes.
`.claude/rules/ingest-d1.md` already flags round-trip cost; this loop predates
the profiles work. Recorded in `docs/issues-and-resolutions.md`.
