### Two real bugs found by GPU-rendered visual inspection

The user asked for the browser tests to actually be looked at (GPUs are
available on this box) rather than trusting only the DOM/geometry suites,
flagging that mobile scroll and HUD overlap looked broken in real use. A
headless Playwright probe (D3D11 ANGLE args from `CLAUDE.md`, real screenshots
at 390×844 across every route) found two bugs neither `test_mobile_responsive.py`
nor `test_mobile_dom.py` catches, because both check element geometry/counts,
not rendered overlap or scroll gesture behaviour:

1. **Mobile scroll was dead on `/spacetrack/brief/` and `/spacetrack/analytics/`.**
   `spacetrack.css`'s `@media (max-width: 768px)` block had an **unscoped**
   `body { overflow: hidden; }`, written for the globe pages
   (`spacetrack-catalog`, which has nothing to scroll). `/spacetrack/brief/`
   and `/spacetrack/analytics/` link `spacetrack.css` too, for shared
   HUD/nav styling, but are plain scrolling documents (`#cesium-container`
   is `display:none` on both) — they inherited the catalog-only rule and
   lost mobile scroll entirely. Confirmed with a wheel-scroll probe before
   the fix (`scrollY` stuck at 0 on both pages, height carries at 826–851px
   of scrollable content) and after (`0 → 26` / `0 → 243`). Fixed by scoping
   the rule to `body[data-page-id="spacetrack-catalog"],
   body[data-page-id="orbital-relay"]`.
2. **The RESULTS panel and the screenshot button shared one anchor point
   on `/spacetrack/` mobile.** `.st-screenshot-btn` and `#results-hud`'s
   mobile rule both used `bottom: calc(130px + var(--sa-bottom)); right:
   calc(8px + var(--sa-right))` — the exact same corner. The 44×44px camera
   icon sat on top of the collapsed RESULTS toggle, truncating its label to
   "RESU" (visible in a real screenshot, invisible to any suite that only
   asserts panel *existence* or *count*). Fixed by moving `#results-hud`
   above the button's 44px height plus an 8px gap:
   `bottom: calc(130px + 44px + 8px + var(--sa-bottom))`. Verified with a
   `getBoundingClientRect()` probe and a screenshot — "// RESULTS" now
   renders in full, clear of both the TIME panel and the camera button.

Both fixes are CSS-only (`public/spacetrack/spacetrack.css`); `npm test` and
the DOM suites stayed green throughout since neither bug was in their
assertion surface — that gap is itself the finding.
