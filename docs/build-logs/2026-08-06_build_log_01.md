## Plan 34 Phase 3.3 — cinematic pass (spec #20)

The full batch (C1–C5) landed in this session's commits; C2 was the wiring bulk,
C5 the close-out. Everything ships behind the persisted `quality.cinematics`
toggle ('high' | 'low'); the repo had zero reduced-motion/quality handling
before this batch.

### C1 — `eclipseShadowFactor` + tests

- Cylinder shadow model in `public/orbit-engine/astro.js` beside
  `footprintRadiusM()`: lit when `p·ŝ ≥ 0` (including the terminator), graded
  smoothstep across the penumbra between umbra radius `earthR − band` and
  `earthR + band`, `band = L·tan(θ_sun)` growing with depth L behind the
  terminator plane (~195 km at GEO depth, ~4.6 km at 1,000 km). Degenerate
  sun/origin → 1 (lit, never NaN); scale-invariant (metres vs km); `earthR`
  defaults to metres to match the ECEF-metre frame the engine feeds it.
- **Not called anywhere — inert until C2.** 14 checks, all closed-form
  geometry (mid-penumbra at perp=R is exactly 0.5, exact umbra/penumbra
  boundaries, monotone ramp, GEO equinox eclipse, off-axis sun, unit
  invariance, domain `L < R/tanθ` pinned across the camera range), wired as
  suite #20 in the orbit-ingest `npm test` chain.

### C2 — quality toggle + eclipse wiring

- **State**: `quality.cinematics` ('high'|'low', default 'high') in
  `spacetrack_state_v1`; `State.STORAGE_KEY` now exported so callers can
  distinguish "saved" from "default".
- **Engine**: `SatEngine.cinematics` field (default 'high') +
  `setCinematics(level)` (validates, no-ops on same, `requestRender()` on
  flip). `_refreshOcclusion()` computes ONE `sunDirectionEcef(this.now())`
  per drawn frame in 'high' and multiplies `alpha = fade × eclipseShadowFactor`,
  skipping it in 'low'. Both `occlusion.test.mjs` purity invariants held
  (baseColor rebuild, no read back off the live primitive, no fade in the
  tick slice).
- **New pure `sunDirectionEcef(date)`** in astro.js (Meeus/NOAA solar
  position: mean longitude + equation of centre + nutation/aberration + GMST
  → ECEF unit vector, ~0.01° accuracy). **Why**: the prep notes'
  `Cesium.SunPosition.compute` does NOT exist in Cesium 1.113's classic build
  (verified live — `Cesium.SunPosition` is undefined; `scene.sun` has no
  positionWC). The Schlyter constant set's epoch bias put the equinox ~1.4
  days late; Meeus constants are exact (equinox −0.010°, solstices ±23.436°,
  J2000 −23.03°) — pinned by the four-anchor declination suite.
- **/orbit/ UI**: CINEMATICS row in the layers HUD + mobile drawer (authored
  twice like revs-toggle; `data-cinematics`/`data-cinematics-label`, synced
  globally). **First-boot device default**: no saved key → 'low' on mobile /
  'high' on desktop, persisted immediately. `isMobile` had to be added to
  orbital-relay.js's hud.js import (not imported before; the ReferenceError
  aborted module eval and left `stationEntities` in TDZ).
- **/spacetrack/** (all 5 pages): `globe.js` applies the saved key at init —
  no toggle UI. /starlink/ + /constellations/ don't import State → engine
  default 'high'. All pages inherit the shared engine.

### C3 — bloom

- `scene.postProcessStages.bloom` behind the same toggle; the engine owns it:
  `_applyCinematics()` sets `bloom.enabled = (cinematics === 'high')`, called
  from the CONSTRUCTOR as well as `setCinematics()` — the constructor call is
  load-bearing, because a page that never calls setCinematics (engine default
  'high', early-return otherwise) would silently never see bloom. All three
  `postProcessStages`/`bloom` accesses are guarded (WebGL2 + lazy getter).
- Uniforms left at Cesium defaults — the canvas renders black in this sandbox
  (Ion 403), so visual tuning (glowOnly/contrast/sigma) is deferred until a
  real renderer can be eyeballed. No page changes.

### C4 — procedural star skyBox

- New `public/orbit-engine/starfield.js`: deterministic 3D star field
  (mulberry32-seeded PRNG, uniform directions, brightness [0.15, 1],
  near-white tints) projected onto six cube faces via right-handed frames
  (t1 × t2 = n), drawn onto 512² canvases, exported as PNG data URLs
  (~78 KB binary total) and handed to `Cesium.SkyBox`.
- **Preempts the lazy Tycho-2 fetch**: Cesium 1.113's `Scene.update` creates
  the default SkyBox (six `tycho2t3_80_*.jpg` from the Cesium CDN) only when
  `scene.skyBox` is undefined. The engine assigns its SkyBox in BOTH levels at
  construction — before the first frame on all four globe pages — so no page
  ever fetches the CDN starfield (probe's request tracker saw zero `tycho2t3`
  hits). 'low' = skyBox hidden (plain black background — product call, see
  Surprises in the handoff).
- `starfield.test.mjs` (21st suite, 20 checks): PRNG determinism; unit-norm
  stars, no NaN; right-handed orthonormal frames; cube corners project to the
  same (u,v) corner on every face; every star inside its owning face; interior
  stars owned by EXACTLY one face; boundary directions read the same edge
  coordinate on both neighbours; back-half and zero-normal-dot rejections;
  stub-2D-context draw tests (no-throw + all faces draw); purity (no
  `Cesium.`, no `document.` outside the canvas sink).
