## Bugs found & fixed (blocker pass)

`npm test` was red and a GPU/parallel e2e run showed a 4-page globe outage when the working tree was first analysed. Root causes, in the order found:

| # | Bug | Root cause | Fix |
|---|---|---|---|
| 1 | `notifications.js` failed to parse — task B module (and its importer `signal.js`) completely dead | `requestPermission` declared as `export function` AND re-exported in the trailing `export { ... }` block → `SyntaxError: Duplicate export` | Dropped the `export` keyword from the declaration; the trailing export block stays |
| 2 | `derive.test.mjs` failed to parse — the whole derive suite never ran | TypeScript non-null assertion `byLaunch.get('2020-012')!.length` is not valid JS | `!.` → `?.` |
| 3 | `npm test` ReferenceError: `debrisFamilyOf is not defined` | Task C's diff **replaced** `debrisFamilyOf` with `groupByLaunch`, but `deriveObjectRow` (derive.js:191) and the existing tests still call it | Restored `debrisFamilyOf` alongside the new `groupByLaunch`/`computeLaunchEntry` |
| 4 | `buildAnalytics` would crash the daily ingest (`Cannot access 'nameOf' before initialization`) | The launch-history block uses `nameOf` before its `const` declaration (declared ~25 lines later) — TDZ error at runtime | Moved the `launch_sites` SELECT + `nameOf` map above the launch block |
| 5 | Site names never resolved in launch rows | `computeLaunchEntry` read `siteMap[siteCode]` — property access on a `Map` is always `undefined` (both callers pass a `Map`) | `siteMap?.get ? siteMap.get(code) : siteMap?.[code]` |
| 6 | `buildAnalytics` crashed (`object is not iterable`) — the daily job would have failed end-to-end | `for (const r of await env.ORBIT_DB.prepare(...).all() || [])` — D1's `.all()` returns `{ results: [...] }`, not an array | Destructure `{ results: allRows }` and iterate that |
| 7 | Launch list was not reverse-chronological — "top 20 most recent" took arbitrary scan order | Sort comparator returned `0` for every pair: it compared with `typeof === 'number'` guards, but `LAUNCH_DATE` is TEXT ISO, so both sides became `0` | ISO strings compare chronologically: `String(...).localeCompare(...)` (fixed in `derive.js` and the endpoint fallback) |
| 8 | `/api/analytics` returned a non-Response — every analytics endpoint test failed (`resp.text is not a function`) | Task C's endpoint code spread `artifactOrDb(...)`'s **Response** objects through `withCitation({...})`, discarding body/headers/stale flags | Merge at the body level: `await res.json()` on both sections, return one `json()` Response with `launches` normalized to an array |
| 9 | `/api/analytics` would full-table-scan D1 on every request in production | The endpoint reads `catalog/launches.json`, but `buildAnalytics` never wrote it (launches were embedded in `analytics.json`) — the R2 read always missed | `buildAnalytics` now writes `catalog/launches.json` (own artifact per plan) as part of the daily build |
| 10 | Fallback site join silently broken | `nameOf.set(...siteNames.map(r => [code, name]))` — `Map.set` called with a spread of tuples sets one key (an array) with `undefined` value | Loop: `for (const r of siteNames) nameOf.set(r.SITE_CODE, r.LAUNCH_SITE)` |
| 11 | Fallback rows were a different shape from the artifact (`type` vs `typeBreakdown`) | Endpoint fallback emitted the first row's `OBJECT_TYPE` as `type`; the artifact carries a real breakdown | Fallback now rolls up `typeBreakdown` per group, matching the artifact shape |
| 12 | **4-globe-page outage** — `/orbit/`, `/spacetrack/`, `/starlink/`, `/constellations/` all dead in the browser (`PAGEERROR: The requested module './astro.js' does not provide an export named 'stationEcfMetres'`) | `comm-links.js` (imported by `sat-engine.js`, the shared engine) imports `stationEcfMetres` from `astro.js`, which never exported it — the import failure killed the whole engine module graph | Added `stationEcfMetres` (WGS-84 geodetic → ECF, metres) to `astro.js` with the same constants/math as the Node-tested copy in `signal/compute.js` |
